# WIPO Madrid Monitor Collector — Руководство пользователя

Собирает классические товарные знаки из Madrid Monitor: сколько знаков по каждому запросу и полные строки результатов.

## Быстрый старт

```bash
# Сборка
go build -o wipos.exe .

# Первый запуск (создаёт конфиг, папки, качает Chromium)
./wipos.exe -gen-config
# Правит config.toml под себя, потом:
./wipos.exe
```

## Режимы работы

| Режим | Флаг | Описание |
|-------|------|----------|
| **replay** (по умолчанию) | `-mode replay` | HTTP POST к `select.jsp` — нет браузера, ~1–3 с/страница. Байт-в-байт идентичен гриду. |
| **browser** | `-mode browser` | Playwright + Chromium. Нужен, когда сайт отдаёт не JSON (обслуживание, блок, изменения). Автоматически включается как фоллбэк. |

## Конфигурация (приоритет: дефолты < config.toml < флаги)

Ключевые параметры:

```toml
input = "task.txt"           # файл с запросами (по одному в строке)
data_dir = "./data"          # куда класть сырой HTML/JSON гридов
results_file = "results.txt" # дата \t запрос \t кол-во
rows_file = "trademarks.tsv" # таймстамп \t запрос \t 11 колонок грида
done_file = "done.lst"       # уже собранные (резюм)
failed_file = "failed.lst"   # неудачные (ретрай на следующем запуске)
short_file = "short.lst"     # собрано, но строк меньше, чем обещал грид

threads = 3                  # параллельные браузеры/воркеры
split_pages = false          # true = один огромный запрос режут на шарды по потокам
max_attempts = 5             # ретраев на запрос

rows_per_page = 100          # 10/30/60/100 (чем больше — тем меньше загрузок)
max_pages = 0                # 0 = все страницы
start_page = 0               # шард: с какой страницы (0 = 1)
end_page = 0                 # шард: по какую (0 = последняя)

submit_gap_ms = 3000         # мин. пауза между поисками с одного IP
submit_jitter_ms = 2500      # случайная добавка сверху
task_pause_ms = 200          # пауза между запросами в одном воркере
task_pause_jitter_ms = 4000

nav_timeout_ms = 120000      # бюджет на загрузку страницы
results_timeout_ms = 180000  # бюджет на появление грида
watchdog_ms = 0              # 0 = авто от таймаутов

headless = false             # true = без окон (нужно для save_pdf)
save_grid = true             # сырой грид (HTML в browser, JSON в replay)
save_full = false            # вся страница целиком
save_pdf = false             # первая страница в PDF (только headless)
```

Прокси: `proxy.lst` (по одному `http://`, `https://`, `socks5://` в строке). Пустой/отсутствует = прямой/VPN. Проверяются реальным запросом перед стартом.

## Входные данные

`task.txt` — по одному запросу в строке. Регистр не важен (приводится к lower). `*` и `?` идут на сайт как есть (вайлдкарды).

## Резюм и повторные запуски

- `done.lst` — собранные запросы пропускаются. BOM в начале файла снимается автоматически.
- `failed.lst` — информационно, на следующем запуске эти запросы пробуются снова.
- `short.lst` — запрос дошёл до конца своих результатов, но строк записано
  меньше, чем обещала позиционная строка (минимум на страницу). Такой запрос
  **не** попадает в `done.lst`: он считается (`results.txt` пишется),
  чекпоинт удаляется, и следующий запуск проходит его заново — дедуп
  дописывает только недостающее. Строка вида
  `query\tcount\trows\tdate` говорит, чего именно не хватило. Второй такой
  случай подряд принимается (дыра в данных, а не в обходе) и остаётся в файле
  как отметка.
- `max_pages` больше **не** помечает запрос собранным: обход остановлен до
  конца данных, чекпоинт сохраняется, следующий запуск продолжает с того же
  места. Иначе частичный запрос выглядел бы законченным навсегда.
- `.ckpt/<query>[.sN]` — последняя записанная страница грида и сколько строк
  у запроса на этой странице. Перезапуск продолжает от `checkpoint+1`, а
  записанное число строк — это то, с чем сверяется проверка полноты.
- Дедуп: хэши строк лежат в `trademarks.tsv.idx` **только по открытым
  запросам** и выбрасываются, как только запрос записан в `done.lst` — иначе
  индекс и память растут со всем, что когда-либо собрано. Файл переписывается
  (уплотняется) при каждом старте. Первый запуск после обновления прогонит
  полный скан строковых файлов, чтобы перестроить индекс в новом формате —
  прогресс в `trademarks.tsv.idx.progress-log`. Опция `-reindex` делает этот
  скан принудительно.

## Типичные сценарии

```bash
# Обычный прогон (replay, 3 потока)
./wipos.exe

# Огромный запрос "*" — распараллелить страницы
./wipos.exe -split-pages -threads 4 -input huge.txt

# Только браузер (отладка, или если replay фоллбэчит часто)
./wipos.exe -mode browser

# Шард для ручного распараллеливания "*" на несколько машин
./wipos.exe -input star.txt -start-page 1 -end-page 5000
./wipos.exe -input star.txt -start-page 5001 -end-page 10000
# ...у каждой машины свой done.lst!
```

## Выходные файлы

- `results.txt` — `2026-09-30	the-royal	163`
- `short.lst` — `tv di gi 8774 2974 2026-10-25` (через таб): обещано, записано, дата
- `trademarks.tsv` — UTF-8 без BOM, 13 колонок: `timestamp`, `query`, `brand`, `holder`, `status`, `origin`, `reg_date`, `reg_number`, `nice`, `vienna`, `record_id`, `record_status`, `number`
- `data/<query>_p<N>.raw` — сырой грид (HTML/JSON) для аудита
- `logs/run.log` — ротируемый лог (32 Мб, 5 файлов)

## Частые проблемы

| Симптом | Лечение |
|---------|---------|
| "results never appeared" / зависание | Увеличь `results_timeout_ms`, проверь прокси/VPN |
| Частые блоки (`KindBlock`) | Подними `submit_gap_ms`, добавь рабочие прокси |
| "home page returned 5xx" / ErrNotJSON | Сайт на техработах — жди или запусти `-mode browser` |
| В логе `SHORT — ... не хватает N строк` | Запрос посчитан, но не закрыт: он пройдётся заново сам, смотри `short.lst` |
| `stopped at max_pages ... NOT marked collected` | Нормально для `max_pages`: чекпоинт сохранён, следующий запуск продолжит |
| Прокси падают на пробе с `HTTP 502/407/403` | Эндпоинт не дотягивает до сайта — он вычищается намеренно, а не ложный срабатывание |
| Первая страница огромного запроса висит | Нормально: первый поиск по свежему профилю может отъесть 30 с, ретрай соберёт за ~3 с |
| Дубликаты в `trademarks.tsv` после перезапуска | Проверь, что `done.lst` не пустой и `.ckpt/` не удалён |

## Производительность (ориентиры на прямом VPN)

| Запрос | Страниц (100/стр) | Replay | Browser |
|--------|-------------------|--------|---------|
| `the-royal` (163) | 2 | ~1.7 с | ~25 с |
| `m-et` (910) | 10 | ~5.8 с | ~120 с |
| `*` (1.54 млн) | 15 430 | ~4–5 ч | ~11 ч |

Replay — дефолт именно за скорость. Browser — страховка.
